# A2UI & A2A 技術核心與商務應用全指南

本指南系統化彙整了 Google 提出的生成式 UI 通訊協定（A2UI）與 Agent-to-Agent（A2A）技術，深入探討其核心運作機制、視覺控制權、安全防護、計費時機以及跨平台 AI 生態系的因應策略。

---

## 一、 核心概念與運作方式

* **A2UI (Agent-to-User/UI Interface)**：採用宣告式 JSON 與原生轉譯，讓 AI 代理（Agent）透過標準化元素跨平台即時算繪互動介面，無需在前端執行任意惡意程式碼。
* **A2A (Agent-to-Agent)**：用於 AI 代理程式之間、或代理與企業平台（如 Gemini Enterprise）之間的安全、標準化通訊協定。
* **核心哲學：解耦 UI 結構與動態資料**。後端 AI 代理發送的訊息流主要包含兩大區塊：
  1. `surfaceUpdate`：定義 UI 元件樹（如 Card, Text, Button），元件間採用平坦化（Flattened）結構互相參照，對大模型「流式輸出（Streaming）」極度友善。
  2. `dataModelUpdate`：利用 JSONPath 語法將業務資料（如價格、名稱）動態綁定至 UI 元件中。

---

## 二、 視覺呈現與樣式控制權

A2UI 渲染出來的畫面**完全可預期且非隨機**，遵循「後端提供語意結構，前端全權決定長相」的原則：

1. **前端開發者的控制權**：全域的字體、顏色（主色調）、圓角與間距（Padding）皆預先定義在前端的轉譯器（Renderer）或 CSS 變數中。
2. **後端 AI 的微調權**：JSON 內可透過佈局元件（如 `Column` 垂直、`Row` 水平）與語意樣式（如 `style: "h2"`）來控制結構排版。
3. **自訂組件（Bring Your Own Component, BYOC）**：前端可將現有的複雜網頁按鈕（內含特定 Class 樣式與動畫）註冊為自訂 A2UI 元件，AI 在 JSON 中直接調用該組件名稱即可原封不動完美呈現。
4. **雙軌樣式設定**：開發者可將 A2UI 容器隔離（例如隔離在 AI 聊天沙盒區內），為 AI 生成的元件定義一套獨立於網站原本風格之外的「AI 科技感」特定樣式。

## 三、 使用者觸發 A2UI 的黃金情境

對使用者而言，他們始終在同一個 Chat 對話框內，但 AI 會根據當下需求，動態變出可互動的圖形介面（UI）最高效地完成任務：

1. **Google 生態系直投（價格比較與商業互動）**：
   * 當使用者於 **Google 生態系**（包含 Google 搜尋的 AI Overviews、Gemini Advanced 聊天室、或 Gemini Enterprise 企業助理）進行對話時，只要網站的 A2UI 接口已註冊至 Google Agent 生態系，當使用者詢問**價格比較**或產品細節時，Google Agent 將 **100% 直接把你網站製作的 A2UI 互動卡片投射在 Google 聊天視窗中**，供使用者直接操作。
2. **動態表單輸入**：當文字聊天需要一來一回確認過多資訊（如訂位人數、日期、時間）時，AI 直接投射出帶有 Date Picker 的表單。
3. **數據視覺化與比較**：要求 AI 統計銷售趨勢或比較產品規格時，AI 直接在對話框內畫出可互動的折線圖、圓餅圖或對比卡片。
4. **工作流審批卡片**：在企業自動化場景中，主管可在 AI 對話框內直接點擊綠色的「核准」或紅色的「拒絕」按鈕，直接觸發後台 ERP 系統。
5. **跨代理商務整合**：當總管 AI（如 Gemini）連線至第三方 AI 子代理（如航空公司 Agent）時，第三方 AI 可跨平台將其官方設計的「劃位卡片」直接投射在總管 AI 的對話視窗中。

## 四、 安全授權與防爬蟲機制

A2A/A2UI 屏棄了傳統網頁「信任瀏覽器」的作法，將防線做在通訊協定與網閘上：

1. **代理人名片宣告（Agent Card Discovery）**：合法 AI 必須出示放置於 `/a2a/.well-known/agent.json` 的公開宣告，網官方驗證後方可建立連線。
2. **網閘級 Model Armor 防護**：請求必須通過 Agent Gateway。網閘會即時掃描輸入 Prompt 的語意，若發現惡意爬取（如提示詞注入攻擊），會在邊緣端（Edge）直接封鎖。
3. **沙盒無執行環境**：A2UI 嚴格禁止在前端執行任何 JavaScript 程式碼，完全杜絕 XSS 惡意腳本注入。
4. **OAuth 使用者身分傳遞（Identity Passthrough）**：當 AI 代理需要執行敏感操作（如查訂單、扣款）時，必須觸發標準的 OAuth 2.0/2.1 流程。人類點擊 A2UI 產生的授權卡片並登入後，網站會發放期間限定且限制範圍（Scoped）的 Access Token 給該 AI 代理，AI 隨後帶上此 Token 呼叫網站 A2A 接口。

## 五、 計費觸發時機與數據觀測

1. **用量計費（Pay-as-you-go）精準時機**：
   * **不計費**：AI 單純默默爬取網站內容當作知識庫時，不觸發 A2UI 費用。
   * **計費觸發點 🚀**：只有當外部使用者展現極高意圖，AI 決定調用你網站的 A2A 接口、呼叫組件，並**開始吐出 A2UI JSON 代碼來渲染卡片時**，大模型的 Token 費用才會被觸發。
2. **OpenTelemetry (OTLP) 數據監測**：
   * 系統會自動記錄引用次數、精確的 Token 消耗量（對應雲端帳單）以及外部 AI 代理的身分（Trace ID）。
   * 透過前端卡片回傳的 Action Event，可精準統計商務轉換率（例如：AI 幫我引出 1000 次卡片，最終帶來 200 筆主動預約）。

## 六、 形象網站導入 A2UI 的策略與跨平台壁壘

1. **形象網站的「雙軌制」優化策略**：
   * 品牌故事、美學設計依舊保留給人類觀看（採用傳統網頁技術）。
   * 商業轉換點（如「聯絡我們」表單、產品規格對比、預約諮詢）則加上 A2A/A2UI API 接口。這能大幅提升網站的 **AXO (AI 體驗優化)** 與 **GEO/AEO** 表現，讓網站在 AI 時代具備「在別人的聊天室裡直接接單」的能力。
2. **跨生態系壁壘與降級處理（Google A2UI vs 非 Google Agent）**：
   * **Google 生態系原生支援**：在 Google 搜尋 AI Overviews、Gemini Advanced 或 Gemini Enterprise 中，A2UI 互動卡片能完整且直接地呈現給使用者。
   * **非 Google Agent 無法顯示 A2UI**：針對非 Google 的 AI Agent（例如 **ChatGPT、Claude** 等），由於其對話視窗環境未內建 A2UI 轉譯器，**無法在使用者對話框內渲染並顯示 A2UI 互動卡片**。
   * **非 Google Agent 的降級處理**：當 ChatGPT (GPTBot) 或 Claude 存取支援 A2UI 的網站時，會將傳回的資料降級轉換為 Markdown 純文字、條列點或標準表格形式呈現。
3. **跨平台通吃策略**：
   * 後端產品資料與商業邏輯核心（Data Model JSON）只需建置一套。
   * **面對 Google 生態系**：透過 A2A 輸出符合 **A2UI 規範** 的 JSON，提供高互動感的富 UI 體驗。
   * **面對 OpenAI / 其他生態系**：透過 **MCP (Model Context Protocol)** 規範提供數據 API 接口。
   * 此雙軌架構能確保網站在不同 AI 平台陣營中，皆具備最佳的被引用率、可讀性與商業轉化能力。
